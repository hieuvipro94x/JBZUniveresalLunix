======================================================================
1. MỤC TIÊU HISTORY
======================================================================

History phải hỗ trợ lọc kết hợp theo:

- Mã hàng
- Kết quả PASS/FAIL
- Hôm nay
- Tuần
- Tháng
- Khoảng ngày tùy chọn
- 2/3/6 tháng
- 1 năm
- Search text nếu hiện tại có
- InspectionType nếu hiện tại có

Các bộ lọc phải kết hợp với nhau.

Ví dụ:

Mã A
+
Tháng 09/2026
+
FAIL

=> chỉ trả FAIL của mã A trong tháng 09/2026.

Không được filter này ghi đè hoặc làm mất filter khác.

======================================================================
2. FILTER MÃ HÀNG
======================================================================

History phải có:

TẤT CẢ MÃ HÀNG

hoặc chọn từng mã riêng.

Ví dụ DB:

Mã A:
PASS 20
FAIL 10

Mã B:
PASS 5
FAIL 2

Filter A:
TOTAL 30
PASS 20
FAIL 10

Filter B:
TOTAL 7
PASS 5
FAIL 2

Không được để record B lọt vào A.

Audit key dùng cho History:

- PartId
- ModelId
- PartNumber
- hoặc business key hiện tại.

Ưu tiên ID ổn định nếu schema đã có.

Nếu cùng Model nhưng khác Part và là hai mã production khác nhau:
History phải tách đúng.

======================================================================
3. FILTER RESULT
======================================================================

Phải hỗ trợ:

- TẤT CẢ
- PASS
- FAIL

TẤT CẢ:
hiển thị cả PASS + FAIL.

PASS:
chỉ hiển thị PASS.

FAIL:
chỉ hiển thị FAIL.

Filter phải chạy ở SQLite query trước pagination.

KHÔNG được:

load 200 row
→ rồi filter PASS/FAIL trong RAM.

======================================================================
4. SUMMARY PHẢI THEO CHÍNH XÁC FILTER
======================================================================

Summary trên màn History gồm:

- TỔNG
- PASS
- FAIL
- TỶ LỆ PASS

phải luôn tính trên filtered dataset hiện tại.

Ví dụ:

A + tháng này + tất cả:

TOTAL 100
PASS 90
FAIL 10
RATE 90%

A + tháng này + PASS:

TOTAL 90
PASS 90
FAIL 0

A + tháng này + FAIL:

TOTAL 10
PASS 0
FAIL 10

Không được:

bảng đang filter A
nhưng summary lấy toàn DB.

Không được:

bảng đang tháng này
nhưng summary tính lifetime.

Rows query và Summary query phải dùng cùng một filter object.

Ưu tiên immutable kiểu:

HistoryQueryFilter
{
    PartId
    Result
    StartDate
    EndDateExclusive
    InspectionType
    SearchText
}

======================================================================
5. FILTER THỜI GIAN
======================================================================

HÔM NAY:

>= Today 00:00
< Tomorrow 00:00

TUẦN NÀY:

nếu không có config khác:
Monday 00:00
→ < Monday tuần kế tiếp.

THÁNG NÀY:

>= ngày 1 tháng hiện tại 00:00
< ngày 1 tháng kế tiếp 00:00.

CUSTOM:

ví dụ:
01/09/2026 -> 30/09/2026

SQL phải dùng:

ResultAt >= 2026-09-01 00:00
AND
ResultAt < 2026-10-01 00:00

Không dùng:

<= 30/09/2026 23:59:59

vì dễ sai milliseconds/ticks.

Khoảng tìm kiếm phải hỗ trợ thực tế:

- 1 ngày
- 1 tuần
- 1 tháng
- 2 tháng
- 3 tháng
- 6 tháng
- 1 năm
- khoảng tùy chọn.

7. PAGE SIZE ĐƯỢC PHÉP - MAX RESULT KHÔNG ĐƯỢC PHÉP
======================================================================

Đúng:

Thiết kế phải là:

→ SQL aggregate toàn bộ filtered dataset
→ load page đầu
→ UI render
→ scroll/load more
→ page tiếp
→ tiếp tục cho tới hết.

Ví dụ:

ban đầu có thể load:
200

sau:
400
600
800
...

đến:
38.426.

======================================================================
8. KEYSET PAGINATION
======================================================================

Ưu tiên keyset pagination.

Sort ổn định:

ORDER BY ResultAt DESC, Id DESC

Cursor page sau theo:

ResultAt < lastResultAt

OR

ResultAt = lastResultAt
AND Id < lastId.

Không dùng OFFSET lớn nếu keyset hiện có thể sử dụng.

Mọi page phải giữ nguyên:

- Part filter
- Result filter
- Date filter
- Search filter
- InspectionType.

======================================================================
9. SUMMARY KHÔNG PHỤ THUỘC PAGE
======================================================================

Nếu:

DB matching = 38.426

page hiện tại mới load 200

thì summary vẫn phải:

TOTAL = 38.426

không phải 200.

PASS/FAIL cũng phải tính toàn filtered dataset.

Có thể hiển thị:

ĐÃ HIỂN THỊ 200 / 38.426

nếu phù hợp UI.

Không bắt buộc thay layout nếu không cần.

======================================================================
10. FILTER RACE / STALE ASYNC
======================================================================

History phải chống callback cũ.

Ví dụ:

đang load:
A + 1 năm

operator đổi ngay sang:
B + tháng này

request A trả về muộn.

Không được append record A vào B.

Cần generation/revision cho history query.

Khi đổi filter:

- clear current rows
- reset cursor
- increment generation
- load summary mới
- load page đầu mới.

Kết quả generation cũ:
discard.

13. EXACTLY-ONCE HISTORY
======================================================================

Audit để chắc chắn:

mỗi physical Production cycle chỉ có đúng 1 Test result.

Không duplicate do:

- EngineChanged nhiều lần
- frame lặp
- popup close
- relay completion
- ProductRemoved
- discard sensor
- scan restart
- UI dispatcher callback muộn.

CycleId phải bảo đảm exactly-once.

PASS:
1 record.

FAIL:
1 record.

Discard/removal:
không tạo thêm Test record.
